# 스타일 가이드

TravelPay 프런트엔드의 디자인 시스템과 화면 구현 규칙입니다. 화면 구성(메인 대시보드·지갑·송금하기·송금 내역)은 Claude Designer 시안(이슈 #54)을 따르고, **색·글꼴·모양·여백은 2026-11-16부터 xe.com을 브라우저 개발자 도구로 실측한 값**을 기준으로 합니다(결정 이력 참고). 값은 모두 `src/index.css`의 `:root` 변수와 공통 클래스로 구현하고, 이 문서가 그 기준입니다. 결정 과정은 맨 아래 [결정 이력](#11-결정-이력)에 있습니다.

> xe.com의 로고·워드마크·이미지·문구는 가져오지 않습니다. 색·글꼴·모양·간격 같은 시각 값만 참고하고 TravelPay 이름·마크·문구를 그대로 씁니다.

**CSS 기여자**

- 김이찬([@ijustsea](https://github.com/ijustsea)): xe.com 실측값 기준 디자인 개편(`fix/css-upgrade`)

## 1. 원칙

- **신뢰감 있는 네이비 그라디언트 핀테크 화면**(xe.com 방식): 대표 남색에서 아주 살짝만 밝아지는 그라디언트 헤더·히어로·푸터와 흰 바탕의 대비로 구성합니다. 버튼·탭·배지는 알약(완전 둥근) 모양, 카드는 흰 바탕 + 1px 연한 테두리(20px 모서리)로 평평하게 두고, 그림자는 히어로 위에 떠 있는 카드에만 씁니다. 강조는 화면당 한 곳(홈 히어로, 지갑 총액 영역, 상세 큰 금액)에만 둡니다. 무거운 애니메이션·3D·차트 라이브러리를 쓰지 않습니다.
- **매매기준율이 환율 정보의 주인공**: 환율이 나오는 곳에서는 매매기준율을 1순위로 보이고, 전일 대비·살 때/팔 때·수수료·기준일은 그보다 낮은 위계로 둡니다(6-7절).
- **아이콘**: 이모지를 쓰지 않습니다. 아이콘은 `components/Icon`의 선 아이콘(24×24, 1.8~2px 선, 직접 그린 SVG)만 쓰고 글자와 함께 둡니다. 아이콘만 있는 버튼에는 `aria-label`을 줍니다.
- **스타일 방식**: Tailwind 같은 CSS 라이브러리를 추가하지 않습니다. 디자인 토큰은 `:root` CSS 변수, 화면은 공통 클래스(`src/index.css`)를 조합합니다. 색·크기 값을 화면 코드나 새 규칙에 직접 쓰지 않고 변수를 씁니다.
- **기능 우선**: 스타일 작업에서 API 호출·권한·라우팅·폼 검증·거래 상태 처리·로딩·오류 처리를 바꾸지 않습니다. 디자인 변경과 기능 변경을 섞지 않습니다.
- **사실만 표시**: 시안에 있어도 API 응답이나 정책에 없는 값은 만들지 않습니다(7절). 결과가 불명확하면 성공처럼 보이게 하지 않습니다.
- **시맨틱 HTML**: `form`·`input`·`select`·`button`·`header`·`main`·`nav`·`section`·`table`을 쓰고 불필요한 `div` 중첩을 줄입니다.
- **반응형**: 기준은 768px(모바일 / 태블릿)과 1024px(태블릿 / 데스크톱)입니다. 375px·768px·1280px에서 잘리거나 겹치거나 가로로 넘치지 않아야 합니다.

## 3. 글씨

### 3-1. 글꼴

`'Zalando Sans', 'Noto Sans KR', system-ui, -apple-system, 'Segoe UI', 'Malgun Gothic', sans-serif`. xe.com이 쓰는 Zalando Sans(영문·숫자, 가변 200~900)와 한글용 Noto Sans KR(가변 100~900)을 `index.html`에서 Google Fonts `css2`로 한 번에 불러옵니다(`display=swap`, 실패하면 시스템 글꼴). 가변 글꼴이라 xe처럼 **550·650 같은 중간 굵기**를 씁니다(본문 400, 메뉴·버튼 500, 강조·제목 550~650). 글자 간격은 전체 `-0.02em`, 큰 제목은 `-0.03em ~ -0.04em`(xe의 음수 자간)입니다. 숫자는 Zalando Sans의 기본(비례) 숫자로 두고 `tabular-nums`는 쓰지 않습니다(이 글꼴의 고정폭 숫자는 모양이 달라 보임). 한글이 어색하게 끊기지 않도록 히어로 문구·푸터·참고 문구에는 `word-break: keep-all`을 둡니다.

### 3-2. 크기 단계

rem 기준은 브라우저 기본(16px)입니다. 모바일 값이 기본이고 768px 이상에서 일부를 키웁니다. 새 스타일은 px·rem을 직접 쓰지 않고 아래 변수를 씁니다.

### 3-3. 화면 배율

시안은 1280px 폭을 기준으로 크기를 정했으므로 `zoom` 배율을 쓰지 않습니다(`--ui-zoom`·`--ui-zoom-chrome` 제거). 가독성이 부족하면 배율이 아니라 3-2 표의 변수를 바꿉니다.

## 4. 공통 UI 클래스

같은 UI를 화면마다 따로 만들지 않고 아래 클래스를 씁니다. 버튼·입력 같은 부품을 React 컴포넌트로 분리하지 않습니다. 공통 컴포넌트는 반복되는 묶음에만 둡니다: `AppLayout`, `StatusBadge`, `Icon`(선 아이콘), `CurrencyMark`(통화 배지), `AmountPresets`(금액 칩), `HistoryTabs`(거래내역 탭), `RateTicker`(환율 티커), `RatesProvider`(티커·홈이 함께 쓰는 환율), `MidRate`(매매기준율 표시, `features/exchange/rateDisplay.tsx`), `RateTable`(홈 환율 표, `features/exchange/RateTable.tsx`), `BrandMark`(로고 마크), `SendBanner`(비로그인 홈 송금 배너), `AmountInput`(금액 칸, 6-8절), `PagePreloader`(화면 코드 미리 받기, 9절).

## 5. 레이아웃 (`AppLayout`)

- **페이지 감싸기**: 화면 루트는 `<section>`입니다. 제목 줄(`.page-head`)은 바탕 위에 두고, **섹션의 직계 자식 `.form`·`.item-list`·`.info`는 카드**로 띄웁니다(판넬 안 판넬을 만들지 않음). 로그인·회원가입 섹션은 `auth-page` 클래스로 520px 가운데 카드가 됩니다.
- **폭**: 헤더·본문·푸터 컨테이너는 가운데 최대 1200px(좌우 `--space-page-x`). 그 안에서 단일 폼 화면은 760px, 목록 화면은 960px, 구역 여러 개로 나누는 넓은 화면(홈·지갑·충전·환율)은 `<section className="page-wide">`로 1200px까지 씁니다.
- **데스크톱(1024px 이상) — 그라디언트 가로 헤더**:
  - `--gradient-hero` 바탕, 높이 88px, 아래 1px 흰색 12% 선. 왼쪽 로고: **흰색 초승달 링 안에 "TP", 링이 열린 오른쪽에 "$"가 걸친 원형 마크**(`BrandMark`, 40px, TP$ = TravelPay Dollar, 바탕 없이 현재 글자색 흰색; 글자는 글꼴이 아니라 도형이라 어디서나 똑같음)와 그 옆 "TravelPay"(19px 650 흰색). xe 로고의 원형 링 구도를 참고하되 모양·글자는 TravelPay 것입니다. 네이비 둥근 사각 바탕에 같은 마크를 얹은 것이 브라우저 탭 아이콘(`public/favicon.svg`)이고, 탭 제목은 "TravelPay: 여행 경비 환전·송금·결제"입니다.

## 6. 화면별 규칙

### 6-1. 홈 (`/`)

디자인 방향의 기준 화면입니다(시안 "1. 메인 대시보드").

- **그라디언트 히어로 띠**(헤더와 이어지는 `--gradient-hero` 바탕): 아래쪽에 **흰 타원 곡선**(`--curve-visible`만큼 보이는 높이 300px 타원, 좌우 -200px)을 깔아 xe 히어로의 둥근 아래 경계를 만듭니다. 왼쪽에 "안녕하세요, ○○님"(16px `--on-navy-muted`), "원화 잔액" 라벨(14px) + 잔액(`--fs-hero` 550, 흰색), 그 아래 주요 기능 버튼(송금하기는 주 버튼, 충전하기·환전하기·결제하기는 `button.on-navy`, 48px 알약, 아이콘 + 글자). 네 버튼은 **같은 크기**입니다(`.home-actions`는 격자: 모바일 2×2, 560px 이상 1×4, 칸 폭을 가득 채움).
- **히어로 오른쪽 카드**(`RateTable`, `.card.raised`, 최대 460px): **오늘의 환율 표** — 6-7a절. 환율이 없으면 카드를 숨기고 히어로는 1열이 됩니다.
- 본문 카드는 곡선 위로 겹쳐 올라옵니다(`margin-top: -72px`).
- **내 지갑** 카드: 통화 카드 그리드(`repeat(auto-fit, minmax(220px, 1fr))`, 카드마다 통화 배지 + 코드·이름, 잔액 `--fs-amount-card`, 쓰임 12px 회색). 오른쪽 위 "지갑 전체 보기 →". 지갑이 없으면 "지갑 만들기", 조회 실패면 문구와 지갑 화면 링크.
- **바로가기** 카드: 거래내역·예약 환전·가맹점 관리(화살표 행).
- **비로그인**(위에서 아래로): ① 소개 히어로(`.home-hero.intro`: "TravelPay" 라벨 · 제목 · 소개 문구, 글이 곡선 위에 오도록 곡선을 낮춤) → ② **오늘의 환율 표**(`RateTable`, 곡선 위로 겹쳐 올라옴, 폭 960px) → ③ **송금 배너**(`SendBanner`). 로그인 입구는 상단 헤더 로그인 버튼 하나뿐이고, 표의 "환전하기"는 `/login?redirect=/exchange?currency=○○○`, 배너의 "지금 송금하기"는 `/login?redirect=/transfers/new`로 가서 로그인 뒤 해당 화면으로 이어집니다. 환율 조회는 공개 API라 로그인 없이 보이고, 불러오지 못하면 표만 숨기고(배너는 곡선 위로 올리지 않음) 송금 배너만 둡니다. 잔액은 부르지 않습니다.

### 6-2. 환율 티커 (`RateTicker`)

### 6-3. 지갑 (`/wallet`)

### 6-4. 충전 (`/wallet/charge`)

- 데스크톱 2열(1024px 이상): 왼쪽 폼 카드, 오른쪽 처리 단계 안내 카드. 좁으면 1열.
- 폼: 금액(`.amount-input` + 금액 칩), 은행 `select`(3자리 코드 문자열, 앞 0 유지), 계좌번호. 버튼 문구는 **충전하기**, 위에 "○○은행 계좌에서 ○○원을 출금해 충전합니다" 안내.
- 안내 카드: 처리 단계 정적 안내(접수 → 은행 출금 → 지갑 적립 → 완료, 상태 코드 원문은 보이지 않음 — #66)와 환불·운영자 확인 설명, 상태 배지 범례. 지금 충전의 실제 상태가 아니므로 진행 표시를 하지 않습니다.

### 6-5. 송금 (`/transfers/new`)

시안 "3. 송금하기"의 모양(제목 줄 오른쪽 단계 표시, 왼쪽 입력 카드 | 오른쪽 요약 카드 2열)을 따릅니다.

- 단계 표시(`.steps`): 정보 입력 → 내용 확인 → 완료. 기존 화면 단계(입력·확인)에 맞추고, 완료는 상세 화면 이동으로 대신합니다.
- 수취인 확인: 서버가 가린 이름(예: 박\*현)과 "송금 가능" 배지(`transferable`). 받을 수 없으면 오류 문구.
- 금액: `.amount-input`, 원화일 때만 금액 칩.
- 오른쪽 요약 카드(1024px 이상, 좁으면 아래): 보내는 금액, **수수료 0원(보내는 금액만 빠집니다)**, 구분선, 총 출금 금액(22px 650). 송금 수수료·적용 환율·송금 사유·예상 도착은 백엔드에 없어 넣지 않습니다.
- 확인 화면: 정보 목록 + 주 버튼(48px 알약). 완료하면 상세 화면으로 이동합니다(완료 모달 없음). 결과를 모르면(연결 실패·5xx) 실패로 단정하지 않고 같은 요청으로 다시 시도하거나 내역을 확인하게 합니다.

### 6-6. 거래내역·상세

시안 "4. 송금 내역 · 상세"의 모양을 따르되, 목록과 상세는 지금처럼 별도 화면(라우팅 유지)입니다.

- 충전·송금·환전·결제·정산 입금 내역 화면 위에 `HistoryTabs`를 둡니다. 각 탭은 자기 도메인의 사용자용 API만 부릅니다. 도메인을 합쳐 주는 API가 없어 "전체" 탭은 두지 않습니다. 탭 이름은 모든 폭에서 **충전 내역 · 송금 내역 · 환전 내역 · 결제 내역 · 정산 내역**이고 각 화면 제목과 같습니다(정산 화면 제목도 "정산 내역", 설명 문구로 "내 가맹점의 정산금이 지갑에 들어온 내역"임을 밝힘). 768px 미만에서는 다섯 탭을 같은 폭으로 나누고 트랙 여백 6px·탭 사이 2px·글씨 13px로 줄여 320px 화면까지 한 줄에 다 보입니다(측정: 320·360·375·390·414px 모두 넘침·글자 잘림 없음). 정산 상세의 돌아가기 문구는 들어온 곳과 관계없이 "정산 내역"이고, 지갑에서 왔으면 지갑의 정산 내역, 가맹점에서 왔으면 가맹점 정산으로 갑니다.
- 목록은 카드 안 행 목록(데스크톱은 날짜·상대·금액·상태가 열처럼 정렬되는 `.data-table` 모양 가능). 빈 목록은 카드 안 가운데 문구.
- 송금 상대방 이름(`counterpartName`, 마스킹): 내역 행 윗줄은 "보냄 · 홍\*동"/"받음 · 홍\*동", 상세 "받는 분"·"보낸 분"은 송금하기 확인 단계와 같이 이름 + 줄바꿈 + 회원 ID(`code.hint`). 이름이 없으면 내역은 "보냄"·"받음"만, 상세는 회원 ID만(기존 모양).
- 상세(`.receipt`): 카드 위쪽 "○○ 상세"(14px 회색) + 상태 배지, 큰 금액(`--fs-amount-lg`), 상대·통화 한 줄, 구분선 아래 정보 목록. 진행 단계 타임라인·영수증 받기·문의하기는 넣지 않습니다.

### 6-6a. 알림 (`/notifications`, 일반회원)

- 헤더 알림 아이콘·배지 모양은 5절입니다. 배지는 읽지 않은 개수만 보여 주고(0이면 숨김, 100 이상 "99+"), 화면 읽기 프로그램에는 "알림, 읽지 않은 알림 N개"로 읽힙니다. 관리자·비로그인에게는 아이콘이 없습니다.
- 목록은 거래내역과 같은 카드 안 행 목록(`.item-list` > `.item`)입니다. 거래내역 탭(`HistoryTabs`)은 붙이지 않고 제목은 "알림"입니다.
  - 윗줄: 문구("홍\*동님이 1,000원을 보냈어요" / "김\*수님에게 1,000원을 보냈어요", 이름이 없으면 "알 수 없는 회원")와, 읽지 않은 알림만 "새 알림" 배지(`badge-processing`). 아랫줄: 송금 완료 시각(KST, `.hint`).
  - 읽은 알림과 읽지 않은 알림은 배지로만 구분합니다(행 바탕색·굵기를 바꾸지 않음).
  - 행 전체가 송금 상세 링크입니다. 누르면 읽음 처리 뒤 이동하고, 이미 삭제된 알림이면 오류 상자 대신 목록 위에 `.hint` 한 줄("삭제된 알림이라 목록을 새로 불러왔습니다.")을 두고 목록을 다시 불러옵니다. 그 밖의 실패만 `p.error`.
  - 빈 목록은 카드 안 가운데 "알림이 없습니다.", 페이지는 다른 목록과 같은 이전·다음(`.pagination`).
- 팝오버·"모두 읽음" 버튼·알림 종류 필터는 두지 않습니다.

### 6-7. 매매기준율 강조

매매기준율(`midRate`)은 환율 정보 중 1순위입니다. 글자 크기만 키우지 않고 **라벨 칩 + 굵은 큰 숫자 + 낮은 위계의 참고 정보**로 구분합니다. 표시는 `MidRate` 컴포넌트 하나로 통일하고, 값은 `formatDecimalText` 문자열 그대로(계산 없음) 씁니다.

| 위계 | 내용 | 모양 |
|---|---|---|
| 1순위 | 매매기준율 | "매매기준율" 라벨 칩(12px 550, 네이비 바탕 흰 글자, 6px 모서리) + 숫자(위치별 크기, 650, `--text-main`) + "원"(본 숫자보다 작게) |
| 2순위 | 전일 대비 | 숫자 바로 옆·아래 ▲▼ 13~14px 550, 2-2절 색 |
| 3순위 | 살 때·팔 때, 수수료 1%, 기준일·수집 시각 | 13~14px `--text-muted`, 한 줄(구분 " · ") |

| 위치 | 적용 |
|---|---|
| 홈 오늘의 환율 | 환율 표(6-7a절): 행마다 통화 배지 + 이름·단위, 기준율 24px 650 + "원", 전일 대비. 카드 머리에는 "기준일 ○"만 적고 "매매기준율" 말은 쓰지 않음 |
| 환율 티커 | 6-2절(`[기준]` 칩 + 흰 굵은 숫자) |
| 환율 화면 (`/exchange-rates`) | 통화마다 카드: 위쪽 통화 배지 + 이름·단위, 라벨 칩 + 기준율 `--fs-rate-lg` + 전일 대비, 구분선 아래 3순위 줄(살 때 · 팔 때, 기준일 · 수집 시각). 데스크톱은 카드 2열, 모바일 1열 |
| 환전 신청 (`/exchange`) | 통화 선택 바로 아래 **기준율 박스**(`--bg-app` 바탕, 12px 모서리): 라벨 칩 + "100엔당" + 기준율 `--fs-rate-lg` + 전일 대비, 아래 3순위 줄 "수수료 1% · 기준일 ○ · 참고용이며 적용 환율은 견적에서 정해집니다". 견적 후 화면의 적용 환율·수수료율·남은 시간 배지는 그대로 |
| 예약 신청 (`/exchange/reservations/new`) | 목표 환율 입력 위에 "지금 매매기준율" 박스(환전 신청과 같은 모양). 목표 입력과 위아래로 나란히 놓여 비교되게 하고, "곧 체결될 수 있음" 안내는 박스 아래 경고 안내로 둡니다 |

- 환전 견적 전 5초 갱신, 예약 화면 갱신 실패 시 마지막 값 유지 등 동작은 바꾸지 않습니다. 값이 없으면 박스 대신 기존 "환율 정보를 불러오지 못했습니다" 문구를 둡니다.

### 6-7a. 홈 환율 표 (`RateTable`)

xe 홈의 환율 표를 참고하되 그래프(스파크라인)는 서버가 과거 시세를 주지 않아 두지 않습니다. 값은 서버 응답 문자열 그대로이고 화면에서 계산하지 않습니다.

- **구성**: 머리(제목 "오늘의 환율" + "기준일 ○" + "환율 전체 →") → **네이비 머리 줄**(통화 · 원화 기준 환율 · 전일 대비, 흰 글자 13px 550, 12px 모서리) → 통화별 행 → "환전 수수료는 1%입니다."(`.rate-meta`, 수치는 `PRE_QUOTE_FEE_RATE`). 이 줄 하나만 두고 다른 수수료 문구는 홈에 쓰지 않습니다.
- **행**: 통화 배지(36px) + 코드 · "일본 엔 · 100엔당" / 기준율(24px 650 + "원") / 전일 대비(상승 빨강 ▲, 하락 파랑 ▼) / **"환전하기 →" 주 버튼**(48px, 다른 버튼과 같은 크기, 로그인 후 `/exchange?currency=○○○`, 비로그인은 로그인 경유).
- **접힘 기준은 화면 폭이 아니라 표 자신의 폭**(CSS 컨테이너 쿼리 `@container`): 560px 이상은 한 줄 4칸, 그보다 좁으면(모바일·히어로 옆 460px 카드) 두 줄 행(위: 통화 · 기준율, 아래: 전일 대비 · 버튼).
- 읽기 프로그램에는 "100엔당 900.2원"처럼 한 문장으로 읽히고, 버튼 이름은 "JPY 환전하기"입니다.

### 6-8. 목록·폼·상세 화면 공통

- 목록: 제목·탭은 바탕 위, 행 목록은 카드. 빈 목록은 카드 안 가운데 문구.
- 폼: 제목·안내는 바탕 위, 입력은 카드 안(입력 50px, 제출 버튼 48px 알약).
- 금액 칸(`AmountInput`, 송금·충전·결제·환전·예약 환전): 숫자와 소수가 있는 통화(CNY, 둘째 자리까지)의 소수점만 입력되고 마이너스·문자·쉼표는 들어가지 않습니다. 칸 안에서 세 자리마다 쉼표를 넣어 보여 주므로 칸 아래에 "100,000원"처럼 금액을 다시 적지 않습니다(입력할 때마다 칸 높이가 바뀌지 않게). 소수가 없는 통화(KRW·JPY)에 소수를 붙여 넣으면 소수점 앞만 남깁니다. 상태 값은 쉼표 없는 숫자 문자열이라 `parseAmount`·금액 칩·전액 버튼은 그대로입니다. 통화별 소수 자릿수는 백엔드 `Currency`(KRW 0·JPY 0·CNY 2, 지갑·환전·원장 서비스 공통)와 같습니다.
- 이메일: 로그인은 서버와 같은 규칙(@ 하나, 공백 없음, 앞뒤 비지 않음, 254자 이하)에 맞지 않으면 로그인 버튼을 끕니다. 서버가 받는 계정은 막지 않도록 서버보다 엄격하게 하지 않습니다. 회원가입은 여기에 더해 흔한 형식(도메인에 점, 예: name@example.com)이 아니면 가입 버튼을 끕니다. 둘 다 칸을 벗어난 뒤에 "이메일 형식을 확인해 주세요."를 보이고, 앞뒤 공백은 지우고 보냅니다.
- 상세: 송금·충전·결제·환전은 `.receipt`. 그 밖 상세는 정보 목록 카드.
- 관리자 화면도 같은 공통 클래스를 따릅니다(필터 폼·목록·정보 목록이 카드, 헤더 메뉴는 관리자 메뉴).

## 7. 넣지 않는 것

시안·와이어프레임에 있었지만 API·정책에 없어 넣지 않은 것입니다. 백엔드가 제공하면 다시 검토합니다.

| 항목 | 이유 |
|---|---|
| 알림 팝오버·환율 알림 | 송금 완료 알림만 API가 있어 헤더 아이콘 + 목록 화면(`/notifications`)으로 둠(팝오버 없음) |
| 총 보유 자산(원화 환산)·자산 비중 바 | 통화 합산·환산 API 없음, 프런트 환산은 금액 계산이라 하지 않음 |
| 7일 환율 추이(스파크라인) | 환율 이력 API 없음(전일 대비만 있음) |
| USD·EUR·GBP·VND 환율 | 서버 지원 통화는 JPY·CNY |
| 빠른 송금 계산기, 해외 송금(받는 분 국가·은행 계좌) | 송금은 지갑 간 송금, 외화 송금 없음 |
| 송금 수수료·송금 사유·예상 도착 | 송금 API에 없음(수수료 0원) |
| 송금 진행 단계 타임라인 | 단계별 시각 데이터 없음(상태만) |
| 영수증 받기·다시 보내기·문의하기 | 기능·API 없음 |
| "추가 인증·암호화 전송" 등 서비스 안내 카드 | 실제 정책 근거 없음 |
| 실명인증 배지, "검증됨", VIP 등급, 2FA 상태 | 데이터 없음 |
| "우대 100%", "면제 혜택" | 환전 수수료는 1% |
| 고객지원 화면(`/support`) | 화면·API 없음 |
| 거래 후 잔액 | 송금·결제 응답에 없음 |
| 송금 완료 모달 | 완료 후 상세 화면 이동 유지 |
| 거래내역 "전체" 탭, 목록 옆 상세 패널(마스터-디테일) | 합쳐 주는 API 없음 / 라우팅 유지 |
| 버튼·입력 컴포넌트 분리(`PrimaryButton`·`FormInput` 등) | 공통 클래스로 통일, 전면 수정 방지 |

## 8. 백엔드 연동 원칙

디자인보다 우선합니다. 자세한 규칙은 [공통 API 규칙](../guide/api-common.md)과 [개발 가이드](../guide/development.md)를 봅니다.

- 백엔드 API 명세를 바꾸지 않고, 실제 엔드포인트·요청·응답 DTO를 확인한 뒤 연동합니다.
- 인증·권한은 기존 구현(`RequireAuth`·`RequireRole`)을 따릅니다.
- 화면은 응답의 실제 상태값으로 그립니다. 응답이 없거나 불명확하면 성공을 만들지 않습니다.
- 금액은 최소 단위 정수(환전만 소수 문자열)로 다루고 소수 연산·문자열 이어 붙이기로 계산하지 않습니다.
- 금전 요청 중에는 버튼을 막고, API 오류·연결 실패·타임아웃을 구분해 안내합니다(5xx·타임아웃은 결과 모름).
- 테스트용 데이터(테스트 계좌 등)는 개발 환경에서만 보입니다.

## 9. 구현 수칙

- **구조 우선**: 폴더 구조·공통 레이아웃·API 클라이언트·라우팅을 먼저 확인하고 새 아키텍처를 들이지 않습니다.
- **의존성**: 디자인 때문에 라이브러리를 설치하지 않습니다(웹 글꼴은 `index.html`의 `<link>`로만).
- **화면 전환이 끊기지 않게**: 화면(페이지)은 라우트별 청크로 나누되 앱이 뜬 뒤 쉬는 시간에 나머지를 미리 받아 둡니다(`lib/lazyPage`, `PagePreloader`). 미리 받은 화면은 `React.lazy`를 거치지 않고 바로 그려서 이동할 때 "화면을 불러오는 중"이 생기지 않습니다. 홈·로그인은 첫 번들에 넣습니다. 서버 데이터를 받는 "불러오는 중" 문구(`.loading`·`.loading-delay`)는 0.4초 뒤에 서서히 나타나, 빨리 끝나는 조회에서는 번쩍이지 않습니다(자리는 처음부터 잡혀 화면이 밀리지 않음).
- **모션**: 새로 뜨는 것은 짧게(0.2~0.5초) 아래에서 올라오며 나타나고(`rise-in`), 눌리는 버튼은 살짝 작아지며(`scale(.98)`), 서랍은 옆에서 들어오고 계정 메뉴는 위에서 펼쳐집니다. 레이아웃을 밀지 않는 `opacity`·`transform`만 씁니다. 화면이 바뀌면 본문 첫 요소가 올라오며 나타납니다(홈은 네이비 히어로가 깜빡이지 않도록 안쪽 내용만, 환율 표 행은 차례로). 거래내역 탭(송금·충전·결제·환전)을 오갈 때는 탭 줄은 그 자리에 두고 아래 내용만 올라옵니다. 조회가 끝나 늦게 붙는 목록 행(`.item-list > li`)과 빈 목록 안내(`.hint.empty`)는 6px 아래에서 0.3초로 나타나고, 행은 앞 다섯 개만 0.03초 간격으로 차례로, 나머지는 함께 뜹니다. 링크로 다른 화면에 가면 맨 위에서 시작하고 뒤로 가기는 브라우저가 위치를 복원합니다. 운영체제의 "움직임 줄이기"를 켜면 등장 모션을 끄고 전환을 거의 즉시로 합니다(`prefers-reduced-motion`). 서랍·메뉴를 닫을 때는 모션 없이 바로 닫힙니다. 다른 화면으로 옮길 때는 View Transitions로 이전 화면이 0.2초 동안 사라지며 새 화면과 겹쳐 바뀝니다(`lib/viewTransition`이 Link·NavLink·navigate의 기본값을 정함, 개별 이동은 `viewTransition`으로 직접 지정). 다만 `replace` 이동(로그인·권한 리다이렉트, 처리 후 상세로 바꾸기), 검색어만 바꾸는 이동(목록 필터·페이지), 뒤로·앞으로 가기, 앱이 뜬 뒤 화면 코드를 아직 다 받지 못한 동안은 전환 없이 바로 바뀝니다(리다이렉트가 겹친 이중 전환·필터마다 화면 전체 깜빡임·브라우저 스크롤 복원과 모바일 스와이프 모션과의 겹침·코드를 기다리며 화면이 굳는 것을 피함). `document.startViewTransition`을 지원하는 브라우저(Chromium 계열 등)에서만 동작하고, 지원하지 않으면 지금처럼 바로 바뀝니다. 마우스 휠 스크롤은 `lib/smoothWheel`이 여러 프레임에 나눠 부드럽게 움직입니다(리눅스 Chromium 계열은 휠 한 칸에 100px을 한 프레임에 건너뛰어 덜컹거림, 측정값). 확대·가로 휠·"움직임 줄이기"·안쪽 스크롤 영역·스크롤 잠금·문서 끝은 브라우저 기본 동작에 맡기고, 스크롤바·키보드·화면 이동으로 위치가 바뀌면 그 위치를 따릅니다. 터치 스크롤은 그대로입니다. 마우스 올림(`:hover`) 효과는 `@media (hover: hover)` 안에만 둬서, 터치 기기에서 탭한 버튼·탭에 hover 색이 남아 선택된 것처럼 보이지 않게 합니다.
- **외부 사이트를 참고할 때**: 색·글꼴·모양·간격 같은 시각 값만 참고하고 로고·이미지·문구는 가져오지 않습니다.
- **변경 절차**: 화면 모양(색·간격·레이아웃)을 바꾸는 변경은 이 문서를 먼저 고치거나 합의를 받습니다. 정리(중복 제거·구조)만 하는 변경은 화면 차이가 없어야 합니다.
- **접근성**: 버튼·입력에 라벨을 둡니다. 아이콘만 있는 요소는 `aria-hidden`이나 접근 가능한 이름을 줍니다. 키보드로 쓸 수 있어야 하고, 서랍 메뉴는 Esc로 닫힙니다. 색만으로 상태를 구분하지 않고, 터치 대상은 44px 이상입니다. 겉모양이 그보다 작은 메뉴 버튼(40px)·헤더 로그인(40px)·탭(36px)·금액 칩(40px)은 크기를 바꾸지 않고 `::after`로 누르는 영역만 44px까지 넓힙니다(주변 간격 안이라 겹치지 않음).
- **검증**: `npm test`·`npm run build`와 함께 375px·768px·1280px에서 헤더·카드·목록·폼·내비게이션·매매기준율 표시를 브라우저로 확인합니다.
