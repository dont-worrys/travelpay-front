# 스타일 가이드

TravelPay 프런트엔드의 디자인 시스템과 화면 구현 규칙입니다. 기준 시안은 Claude Designer로 확정한 "TravelPay 디자인 시안"(메인 대시보드·지갑·송금하기·송금 내역 4개 보드, 이슈 #54)입니다. 값은 모두 `src/index.css`의 `:root` 변수와 공통 클래스로 구현하고, 이 문서가 그 기준입니다. 결정 과정은 맨 아래 [결정 이력](#11-결정-이력)에 있습니다.

## 1. 원칙

- **신뢰감 있는 네이비 핀테크 화면**(XE 방향 재해석): 네이비 헤더·히어로 띠와 흰 카드의 대비로 구성합니다. 카드는 흰 바탕 + 1px 연한 테두리로 평평하게 두고, 강조는 화면당 한 곳(홈 히어로, 지갑 총액 영역, 상세 큰 금액)에만 둡니다. 무거운 애니메이션·3D·차트 라이브러리를 쓰지 않습니다.
- **매매기준율이 환율 정보의 주인공**: 환율이 나오는 곳에서는 매매기준율을 1순위로 보이고, 전일 대비·살 때/팔 때·수수료·기준일은 그보다 낮은 위계로 둡니다(6-7절).
- **아이콘**: 이모지를 쓰지 않습니다. 아이콘은 `components/Icon`의 선 아이콘(24×24, 1.8~2px 선, 직접 그린 SVG)만 쓰고 글자와 함께 둡니다. 아이콘만 있는 버튼에는 `aria-label`을 줍니다.
- **스타일 방식**: Tailwind 같은 CSS 라이브러리를 추가하지 않습니다. 디자인 토큰은 `:root` CSS 변수, 화면은 공통 클래스(`src/index.css`)를 조합합니다. 색·크기 값을 화면 코드나 새 규칙에 직접 쓰지 않고 변수를 씁니다.
- **기능 우선**: 스타일 작업에서 API 호출·권한·라우팅·폼 검증·거래 상태 처리·로딩·오류 처리를 바꾸지 않습니다. 디자인 변경과 기능 변경을 섞지 않습니다.
- **사실만 표시**: 시안에 있어도 API 응답이나 정책에 없는 값은 만들지 않습니다(7절). 결과가 불명확하면 성공처럼 보이게 하지 않습니다.
- **시맨틱 HTML**: `form`·`input`·`select`·`button`·`header`·`main`·`nav`·`section`·`table`을 쓰고 불필요한 `div` 중첩을 줄입니다.
- **반응형**: 기준은 768px(모바일 / 태블릿)과 1024px(태블릿 / 데스크톱)입니다. 375px·768px·1280px에서 잘리거나 겹치거나 가로로 넘치지 않아야 합니다.

### 2-2. 상태 색

상태별 색은 화면마다 정하지 않고 상태 매핑 객체(`features/*/status.ts` 등)에서 계열(`tone`)만 고르면 `StatusBadge`가 표준 클래스를 붙입니다. 백엔드에 없는 상태를 추가하지 않습니다. 배지는 12px 600, 안쪽 3px 8px, 모서리 6px입니다.

| 계열(`tone`) | 배지 클래스 | 바탕 / 글자 | 쓰는 상태 |

| `success` | `badge-completed` | `#E6F4EC` / `#0E6B43` | 완료(`COMPLETED`·`APPROVED`·`PAID`·체결) |

## 3. 글씨

### 3-1. 글꼴

`Inter, 'Noto Sans KR', Pretendard, system-ui, sans-serif`. Inter(400·500·600·700)와 Noto Sans KR(400·500·700)은 `index.html`에서 Google Fonts `css2`로 불러옵니다(`display=swap`, 실패하면 Pretendard·시스템 글꼴). 금액·환율·ID는 `font-variant-numeric: tabular-nums`로 숫자 폭을 맞춥니다. 큰 숫자·제목은 `letter-spacing: -0.01em ~ -0.02em`입니다.

### 3-2. 크기 단계

rem 기준은 브라우저 기본(16px)입니다. 모바일 값이 기본이고 768px 이상에서 일부를 키웁니다. 새 스타일은 px·rem을 직접 쓰지 않고 아래 변수를 씁니다.

| 변수 | 모바일 / 데스크톱 | 대상 |
|---|---|---|
| `--fs-hero` | 32 / 48px (700) | 홈 히어로 잔액 |
| `--fs-balance` | 28 / 40px (700) | 지갑 총액·선택 통화 잔액 |
| `--fs-amount-lg` | 28 / 32px (700) | 상세 큰 금액 |

### 3-3. 화면 배율

시안은 1280px 폭을 기준으로 크기를 정했으므로 `zoom` 배율을 쓰지 않습니다(`--ui-zoom`·`--ui-zoom-chrome` 제거). 가독성이 부족하면 배율이 아니라 3-2 표의 변수를 바꿉니다.

| `.mid-rate` / `.mid-rate-box` / `.rate-meta` | 매매기준율 표시(`MidRate`, `.md`는 22~24px) / 기준율 박스(`--bg-app`, 12px 모서리) / 3순위 참고 줄(13px 회색) |
| `.summary-list` | 요약 카드 dl(이름 회색 왼쪽, 값 오른쪽 600, `.summary-total` 행은 위 구분선 + 22px 700) |
| `.visually-hidden` | 화면 읽기 프로그램용 숨김 제목·라벨 |

## 5. 레이아웃 (`AppLayout`)

- **페이지 감싸기**: 화면 루트는 `<section>`입니다. 제목 줄(`.page-head`)은 바탕 위에 두고, **섹션의 직계 자식 `.form`·`.item-list`·`.info`는 카드**로 띄웁니다(판넬 안 판넬을 만들지 않음).
- **폭**: 헤더·본문 컨테이너는 가운데 최대 1280px(좌우 `--space-page-x`). 그 안에서 단일 폼 화면은 760px, 목록 화면은 960px, 구역 여러 개로 나누는 넓은 화면(홈·지갑·충전·환율)은 `<section className="page-wide">`로 1280px까지 씁니다.
- **데스크톱(1024px 이상) — 가로 헤더**:
  - 네이비(`--navy`) 헤더, 안쪽 위아래 14px. 왼쪽 로고(파란 원 + 위 화살표 마크 30px, "TravelPay" 20px 700 흰색).
  - 가운데 가로 메뉴(`nav`): 메뉴마다 10px 14px, 8px 모서리, 15px. 비선택 `--on-navy-muted` 500, 선택 `--navy-soft` 바탕 흰 글자 600(`aria-current="page"`). 공간이 모자라면 줄바꿈합니다.
  - 오른쪽: 환율 티커(6-2절), 이름 첫 글자 아바타(40px 원, `--primary-subtle` 바탕) + "○○ 님", 계정 메뉴(내 정보·비밀번호 변경·로그아웃)는 아바타를 누르면 열리는 메뉴로 둡니다.
  - 사이드바는 쓰지 않습니다.
- **태블릿·모바일(1024px 미만)**:
  - 네이비 미니 헤더(56px): 로고, 아바타 + 이름(말줄임, "(관리자)" 숨김), "메뉴" 버튼. 메뉴 버튼은 전체 메뉴를 서랍으로 엽니다(네이비 바탕, 바깥 누름·Esc·화면 이동으로 닫힘). 계정 메뉴도 서랍 아래에 둡니다.
  - 768px 미만 일반회원은 하단 고정 탭바(56px, 흰 바탕 + 위 1px 테두리): 홈 · 지갑·충전 · 송금(`/transfers/new`) · 환전 · 내역(`/payments`에서 시작, 거래내역 5화면에서 선택 표시). 아이콘 위·글자 아래, 선택 탭은 `--primary`. 본문 아래 72px 여백.
  - 환율 티커는 768px 이상에서만 헤더에 보입니다.
- **메뉴 분기**: 일반회원·관리자(`MASTER`)·비로그인 메뉴와 링크 텍스트·경로는 기존 그대로 둡니다(테스트·사용자 혼동 방지). 관리자에게는 하단 탭바와 환율 티커를 보이지 않습니다.

## 6. 화면별 규칙

### 6-1. 홈 (`/`)

디자인 방향의 기준 화면입니다(시안 "1. 메인 대시보드").

- **네이비 히어로 띠**(헤더와 이어지는 `--navy` 바탕, 위 40px·아래 120px): 왼쪽에 "안녕하세요, ○○님"(16px `--on-navy-muted`), "원화 잔액" 라벨(14px) + 잔액(`--fs-hero`, 흰색), 그 아래 주요 기능 버튼(송금하기는 주 버튼, 충전하기·환전하기·결제는 `button.on-navy`, 48px, 아이콘 + 글자).
- **히어로 오른쪽 카드**(`.card.raised`, 최대 460px): **오늘의 환율** — JPY·CNY 매매기준율을 강조 표시(6-7절)하고 전일 대비, 머리에 "매매기준율 · 기준일" 라벨과 "환율 전체 →" 링크, 아래 "환전 수수료 1%는 견적에서 더해져요" 안내와 "환전하기" 주 버튼. 환율이 없으면 카드를 숨기고 히어로는 1열이 됩니다.
- 본문 카드는 히어로 아래쪽에 겹쳐 올라옵니다(`margin-top: -72px`).
- **내 지갑** 카드: 통화 카드 그리드(`repeat(auto-fit, minmax(220px, 1fr))`, 카드마다 통화 배지 + 코드·이름, 잔액 `--fs-amount-card`, 쓰임 12px 회색). 오른쪽 위 "지갑 전체 보기 →". 지갑이 없으면 "지갑 만들기", 조회 실패면 문구와 지갑 화면 링크.
- **바로가기** 카드: 거래내역·예약 환전·가맹점 관리(화살표 행).
- 비로그인: 같은 네이비 히어로에 소개 문구와 로그인·회원가입, 오른쪽 카드 자리에는 기능 소개, 아래 환율 보기 링크. 잔액·환율을 부르지 않습니다.
- 1024px 미만은 히어로가 1열(카드가 잔액 아래), 본문 카드도 1열입니다.

### 6-2. 환율 티커 (`RateTicker`)

- 헤더 오른쪽, 네이비 위에 둡니다. 서버가 지원하는 JPY·CNY만 고르고 매매기준율을 보여 줍니다.
- 위계: `[기준]` 라벨 칩(12px 600, `--navy-soft` 바탕 흰 글자) → **기준율 숫자**(15px 700 흰색, tabular-nums) + "KRW"(13px `--on-navy-muted`) → 통화 선택(작은 선택 상자, `--on-navy-muted`). 전일 대비가 있으면 숫자 옆에 ▲▼ 13px(네이비 위에서는 상승 `#FF8A84`, 하락 `#8FA6FF`로 대비 확보, 화살표 글자 함께).
- 환율은 레이아웃의 `RatesProvider`가 처음 1회와 5분마다만 조회하고 티커와 홈이 같은 응답을 씁니다. 통화를 바꿔도 다시 조회하지 않고, 실패하면 숨깁니다. 누르면 환율 화면으로 갑니다.

### 6-3. 지갑 (`/wallet`)

시안 "2. 지갑 · 통화별 잔액" 구성에서 API에 있는 것만 씁니다.

- 제목 줄: "내 지갑" + 설명, 오른쪽 충전하기(보조)·송금하기(주).
- **보유 통화** 카드: 통화 행(40px 배지, 코드 600 + 이름 12px 회색, 오른쪽 잔액 16px 700). 행 오른쪽 "충전"/"원화로 환전" 링크는 기존 그대로.
- **최근 충전** 카드: 행 목록 + "전체 보기 →".
- **최근 정산 입금** 카드: 최근 충전 아래, 정산 입금이 있을 때만(가맹점 주인). 행 = 가맹점 이름 + 입금 시각, 오른쪽 +금액(초록). "전체 보기 →"는 `/wallet/settlements`.
- 원화 환산 총액·자산 비중 바·7일 추이는 넣지 않습니다(7절).

### 6-4. 충전 (`/wallet/charge`)

- 데스크톱 2열(1024px 이상): 왼쪽 폼 카드, 오른쪽 처리 단계 안내 카드. 좁으면 1열.
- 폼: 금액(`.amount-input` + 금액 칩), 은행 `select`(3자리 코드 문자열, 앞 0 유지), 계좌번호. 버튼 문구는 **충전하기**, 위에 "○○은행 계좌에서 ○○원을 출금해 충전합니다" 안내.
- 안내 카드: 처리 단계 정적 안내(접수 `REQUESTED` → 은행 출금 `BANK_PROCESSING` → 지갑 적립 `CREDIT_PROCESSING` → 완료 `COMPLETED`)와 환불·운영자 확인 설명, 상태 배지 범례. 지금 충전의 실제 상태가 아니므로 진행 표시를 하지 않습니다.
- 테스트 계좌 버튼은 개발 환경에서만 보입니다(`VITE_LOCAL_TEST_ACCOUNT`). 한도·실명 일치 안내는 지우지 않습니다.

### 6-5. 송금 (`/transfers/new`)

시안 "3. 송금하기"의 모양(제목 줄 오른쪽 단계 표시, 왼쪽 입력 카드 | 오른쪽 요약 카드 2열)을 따릅니다.

- 단계 표시(`.steps`): 정보 입력 → 내용 확인 → 완료. 기존 화면 단계(입력·확인)에 맞추고, 완료는 상세 화면 이동으로 대신합니다.
- 수취인 확인: 서버가 가린 이름(예: 박\*현)과 "송금 가능" 배지(`transferable`). 받을 수 없으면 오류 문구.
- 금액: `.amount-input`, 원화일 때만 금액 칩.
- 오른쪽 요약 카드(1024px 이상, 좁으면 아래): 보내는 금액, **수수료 0원(보내는 금액만 빠집니다)**, 구분선, 총 출금 금액(22px 700). 송금 수수료·적용 환율·송금 사유·예상 도착은 백엔드에 없어 넣지 않습니다.
- 확인 화면: 정보 목록 + 주 버튼(52px). 완료하면 상세 화면으로 이동합니다(완료 모달 없음). 결과를 모르면(연결 실패·5xx) 실패로 단정하지 않고 같은 요청으로 다시 시도하거나 내역을 확인하게 합니다.

### 6-6. 거래내역·상세

시안 "4. 송금 내역 · 상세"의 모양을 따르되, 목록과 상세는 지금처럼 별도 화면(라우팅 유지)입니다.

- 충전·송금·환전·결제·정산 입금 내역 화면 위에 `HistoryTabs`를 둡니다. 각 탭은 자기 도메인의 사용자용 API만 부릅니다. 도메인을 합쳐 주는 API가 없어 "전체" 탭은 두지 않습니다.
- 목록은 카드 안 행 목록(데스크톱은 날짜·상대·금액·상태가 열처럼 정렬되는 `.data-table` 모양 가능). 빈 목록은 카드 안 가운데 문구.
- 상세(`.receipt`): 카드 위쪽 "○○ 상세"(14px 회색) + 상태 배지, 큰 금액(`--fs-amount-lg`), 상대·통화 한 줄, 구분선 아래 정보 목록. 진행 단계 타임라인·영수증 받기·문의하기는 넣지 않습니다.

### 6-7. 매매기준율 강조

매매기준율(`midRate`)은 환율 정보 중 1순위입니다. 글자 크기만 키우지 않고 **라벨 칩 + 굵은 큰 숫자 + 낮은 위계의 참고 정보**로 구분합니다. 표시는 `MidRate` 컴포넌트 하나로 통일하고, 값은 `formatDecimalText` 문자열 그대로(계산 없음) 씁니다.

| 위계 | 내용 | 모양 |
|---|---|---|
| 1순위 | 매매기준율 | "매매기준율" 라벨 칩(12px 600, 네이비 바탕 흰 글자, 6px 모서리) + 숫자(위치별 크기, 700, `--text-main`, tabular-nums) + "원"(본 숫자보다 작게, 600) |
| 2순위 | 전일 대비 | 숫자 바로 옆·아래 ▲▼ 13~14px 600, 2-2절 색 |
| 3순위 | 살 때·팔 때, 수수료 1%, 기준일·수집 시각 | 13~14px `--text-muted`, 한 줄(구분 " · ") |

| 위치 | 적용 |
|---|---|
| 홈 오늘의 환율 | 히어로 카드 행마다 통화 배지 + 단위, 오른쪽 기준율 22~24px + 전일 대비. 카드 머리에 "매매기준율 · 기준일" |
| 환율 티커 | 6-2절(`[기준]` 칩 + 흰 굵은 숫자) |
| 환율 화면 (`/exchange-rates`) | 통화마다 카드: 위쪽 통화 배지 + 이름·단위, 라벨 칩 + 기준율 `--fs-rate-lg` + 전일 대비, 구분선 아래 3순위 줄(살 때 · 팔 때, 기준일 · 수집 시각). 데스크톱은 카드 2열, 모바일 1열 |
| 환전 신청 (`/exchange`) | 통화 선택 바로 아래 **기준율 박스**(`--bg-app` 바탕, 12px 모서리): 라벨 칩 + "100엔당" + 기준율 `--fs-rate-lg` + 전일 대비, 아래 3순위 줄 "수수료 1% · 기준일 ○ · 참고용이며 적용 환율은 견적에서 정해집니다". 견적 후 화면의 적용 환율·수수료율·남은 시간 배지는 그대로 |
| 예약 신청 (`/exchange/reservations/new`) | 목표 환율 입력 위에 "지금 매매기준율" 박스(환전 신청과 같은 모양). 목표 입력과 위아래로 나란히 놓여 비교되게 하고, "곧 체결될 수 있음" 안내는 박스 아래 경고 안내로 둡니다 |

- 환전 견적 전 5초 갱신, 예약 화면 갱신 실패 시 마지막 값 유지 등 동작은 바꾸지 않습니다. 값이 없으면 박스 대신 기존 "환율 정보를 불러오지 못했습니다" 문구를 둡니다.

### 6-8. 목록·폼·상세 화면 공통

- 목록: 제목·탭은 바탕 위, 행 목록은 카드. 빈 목록은 카드 안 가운데 문구.
- 폼: 제목·안내는 바탕 위, 입력은 카드 안(입력 44px, 제출 버튼 52px).
- 상세: 송금·충전·결제·환전은 `.receipt`. 그 밖 상세는 정보 목록 카드.
- 관리자 화면도 같은 공통 클래스를 따릅니다(필터 폼·목록·정보 목록이 카드, 헤더 메뉴는 관리자 메뉴).

## 7. 넣지 않는 것

시안·와이어프레임에 있었지만 API·정책에 없어 넣지 않은 것입니다. 백엔드가 제공하면 다시 검토합니다.

| 항목 | 이유 |
|---|---|
| 알림 벨·알림 팝오버·환율 알림 | 알림 API 없음 |
| 총 보유 자산(원화 환산)·자산 비중 바 | 통화 합산·환산 API 없음, 프런트 환산은 금액 계산이라 하지 않음 |
| 7일 환율 추이(스파크라인) | 환율 이력 API 없음(전일 대비만 있음) |
| USD·EUR·GBP·VND 환율 | 서버 지원 통화는 JPY·CNY |
| 빠른 송금 계산기, 해외 송금(받는 분 국가·은행 계좌) | 송금은 지갑 간 송금, 외화 송금 없음 |
| 송금 수수료·송금 사유·예상 도착 | 송금 API에 없음(수수료 0원) |
| 송금 진행 단계 타임라인 | 단계별 시각 데이터 없음(상태만) |
| 영수증 받기·다시 보내기·문의하기 | 기능·API 없음 |
| "추가 인증·암호화 전송" 등 서비스 안내 카드 | 실제 정책 근거 없음 |
| 실명인증 배지, "검증됨", VIP 등급, 2FA 상태 | 데이터 없음 |
| "우대 100%", "면제 혜택" | 환전 수수료는 1% |
| 고객지원 화면(`/support`) | 화면·API 없음 |
| 거래 후 잔액 | 송금·결제 응답에 없음 |
| 송금 완료 모달 | 완료 후 상세 화면 이동 유지 |
| 거래내역 "전체" 탭, 목록 옆 상세 패널(마스터-디테일) | 합쳐 주는 API 없음 / 라우팅 유지 |
| 버튼·입력 컴포넌트 분리(`PrimaryButton`·`FormInput` 등) | 공통 클래스로 통일, 전면 수정 방지 |

## 8. 백엔드 연동 원칙

디자인보다 우선합니다. 자세한 규칙은 [공통 API 규칙](../guide/api-common.md)과 [개발 가이드](../guide/development.md)를 봅니다.

- 백엔드 API 명세를 바꾸지 않고, 실제 엔드포인트·요청·응답 DTO를 확인한 뒤 연동합니다.
- 인증·권한은 기존 구현(`RequireAuth`·`RequireRole`)을 따릅니다.
- 화면은 응답의 실제 상태값으로 그립니다. 응답이 없거나 불명확하면 성공을 만들지 않습니다.
- 금액은 최소 단위 정수(환전만 소수 문자열)로 다루고 소수 연산·문자열 이어 붙이기로 계산하지 않습니다.
- 금전 요청 중에는 버튼을 막고, API 오류·연결 실패·타임아웃을 구분해 안내합니다(5xx·타임아웃은 결과 모름).
- 테스트용 데이터(테스트 계좌 등)는 개발 환경에서만 보입니다.

## 9. 구현 수칙

- **구조 우선**: 폴더 구조·공통 레이아웃·API 클라이언트·라우팅을 먼저 확인하고 새 아키텍처를 들이지 않습니다.
- **의존성**: 디자인 때문에 라이브러리를 설치하지 않습니다(웹 글꼴은 `index.html`의 `<link>`로만).
- **변경 절차**: 화면 모양(색·간격·레이아웃)을 바꾸는 변경은 이 문서를 먼저 고치거나 합의를 받습니다. 정리(중복 제거·구조)만 하는 변경은 화면 차이가 없어야 합니다.
- **접근성**: 버튼·입력에 라벨을 둡니다. 아이콘만 있는 요소는 `aria-hidden`이나 접근 가능한 이름을 줍니다. 키보드로 쓸 수 있어야 하고, 서랍 메뉴는 Esc로 닫힙니다. 색만으로 상태를 구분하지 않고, 터치 대상은 44px 이상입니다.
- **검증**: `npm test`·`npm run build`와 함께 375px·768px·1280px에서 헤더·카드·목록·폼·내비게이션·매매기준율 표시를 브라우저로 확인합니다.
