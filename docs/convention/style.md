# 스타일 가이드

TravelPay 프런트엔드의 디자인 시스템과 화면 구현 규칙입니다. 값은 모두 `src/index.css`의 `:root` 변수와 공통 클래스로 구현되어 있고, 이 문서는 그 기준입니다. 결정 과정은 맨 아래 [결정 이력](#11-결정-이력)에 있습니다.

## 1. 원칙

- **가볍고 깔끔한 핀테크 화면**(Wise·Revolut 참고): 박스를 겹겹이 두지 않고, 강조는 화면당 한 곳(잔액 영역)에만 둡니다. 나머지는 바탕 위 흰 판넬과 얇은 행 구분선으로 정리합니다. 무거운 애니메이션·3D·차트 라이브러리를 쓰지 않습니다.
- **아이콘**: 이모지를 쓰지 않습니다. 아이콘은 `components/Icon`의 선 아이콘(24×24, 1.8px 선, 직접 그린 SVG)만 쓰고 글자와 함께 둡니다.
- **스타일 방식**: Tailwind 같은 CSS 라이브러리를 추가하지 않습니다. 디자인 토큰은 `:root` CSS 변수, 화면은 공통 클래스(`src/index.css`)를 조합합니다. 색·크기 값을 화면 코드나 새 규칙에 직접 쓰지 않고 변수를 씁니다.
- **기능 우선**: 스타일 작업에서 API 호출·권한·라우팅·폼 검증·거래 상태 처리·로딩·오류 처리를 바꾸지 않습니다. 디자인 변경과 기능 변경을 섞지 않습니다.
- **사실만 표시**: API 응답이나 정책에 없는 값(인증 배지, 우대율, 알림, 거래 후 잔액 등)을 화면 예시라는 이유로 만들지 않습니다. 결과가 불명확하면 성공처럼 보이게 하지 않습니다.
- **시맨틱 HTML**: `form`·`input`·`select`·`button`·`header`·`main`·`nav`·`section`을 쓰고 불필요한 `div` 중첩을 줄입니다.
- **반응형**: 기준은 768px입니다(미만 모바일, 이상 데스크톱). 375px·768px·1280px에서 잘리거나 넘치지 않아야 합니다.

### 2-2. 상태 색

상태별 색은 화면마다 정하지 않고 상태 매핑 객체(`features/*/status.ts` 등)에서 계열(`tone`)만 고르면 `StatusBadge`가 표준 클래스를 붙입니다. 백엔드에 없는 상태를 추가하지 않습니다.

| 계열(`tone`) | 배지 클래스 | 색 | 쓰는 상태 |
|---|---|---|---|
| `success` | `badge-completed` | emerald 50/700/200 | 완료(`COMPLETED`·`APPROVED`·`PAID`·체결) |
| `info`, `warn` | `badge-processing` | amber 50/700/200 | 처리 중·대기·환불 신청·환불 중 |
| `danger` | `badge-failed` | rose 50/700/200 | 실패·거절 |
| `review` | `badge-manual` | indigo 50/700/200 | 확인 중(`MANUAL_REVIEW`) |
| `neutral` | `badge-neutral` | slate | 취소·만료·환불됨 |

입력 오류 테두리는 `--status-failed-strong`(rose-500)입니다. 환율 전일 대비는 팀 지정 색으로 상승 빨강 ▲, 하락 파랑 ▼, 변동 없음 회색입니다. 색만으로 구분하지 않도록 배지·화살표에는 항상 글자를 함께 둡니다.

## 3. 글씨

### 3-1. 크기 단계

rem 기준은 브라우저 기본(16px)이고 본문 크기는 `body`에서 정합니다. 모바일 값이 기본이고 768px 이상에서 일부를 키웁니다. 새 스타일은 px·rem을 직접 쓰지 않고 아래 변수를 씁니다. 글꼴은 Pretendard → Inter → 시스템 sans-serif 순입니다(웹 글꼴은 불러오지 않음).

| 변수 | 모바일 / 데스크톱 | 대상 |
|---|---|---|
| `--fs-h1` | 24 / 28px | 페이지 제목(bold) |
| `--fs-h2` | 18px | 카드·구역 제목(bold) |
| `--fs-h3` | 16px | 소제목, 충전 단계 이름 |
| `--fs-body` | 15 / 16px | 본문, 정보 목록 값, 알림·오류 박스 |
| `--fs-control` | 16 / 15px | 입력·선택(모바일 16px은 iOS 확대 방지) |
| `--fs-button` | 15px | 버튼 |
| `--fs-tab` · `--fs-nav` | 15px | 화면 안 탭, 거래내역 탭, 사이드바 메뉴 |
| `--fs-item` | 16px | 내역 첫 줄 |
| `--fs-amount` | 16 / 17px | 목록 금액(semibold) |
| `--fs-amount-lg` | 28 / 32px | 상세 큰 금액(bold) |
| `--fs-balance` | 26 / 30px | 잔액(bold) |
| `--fs-sm` | 14px | 라벨, 안내 문구(`.hint`), 입력 오류, 정보 목록 이름, 안내 박스 |
| `--fs-xs` | 13px | 보조 정보: 내역 둘째 줄, 위치 표시, 상단 바, 하단 탭바, 칩, 코드 |
| `--fs-2xs` | 12px | 배지, 단계 번호, 로고 부제(꼭 작아야 하는 곳만) |

`.hint`는 안내 문단에도 쓰이므로 기본 14px이고, 내역 둘째 줄처럼 보조 정보 자리에서만 13px입니다. 금액·환율·ID는 `font-variant-numeric: tabular-nums`로 숫자 폭을 맞춥니다.

### 3-2. 화면 배율

위 표는 기준 크기이고, 시연·가독성을 위해 영역별로 `zoom`을 겁니다. 배율을 바꿀 때는 표 값이 아니라 이 변수만 바꿉니다.

| 변수 | 적용 | 1280px 이상 | 768~1279px | 모바일 |
|---|---|---|---|---|
| `--ui-zoom-chrome` | 사이드바, 상단 바 | 1.2 | 1.1 | 1 |
| `--ui-zoom` | 본문(`.app-main`) | 1.2 | 1.1 | 1 |

모바일은 375px 레이아웃을 지키려고 배율을 걸지 않습니다. 사이드바 높이는 `100vh / --ui-zoom-chrome`으로 나눠 화면에 맞춥니다.

## 5. 레이아웃 (`AppLayout`)

- **페이지 감싸기**: 화면 루트는 `<section>`입니다. 바깥 카드 없이 제목·안내·탭·버튼 줄은 바탕 위에 두고, **섹션의 직계 자식 `.form`·`.item-list`·`.info`만 판넬**로 띄웁니다(화면 코드를 고치지 않고 모든 화면이 같은 구성을 가짐, 판넬 안 판넬을 만들지 않음).
- **폭**: 일반 화면은 가운데 760px, 목록 화면(직계 `.item-list`나 거래내역 탭이 있는 화면)은 960px, 구역 여러 개로 나누는 넓은 화면(홈·충전)은 `<section className="page-wide">`로 1180px까지(그 밖 본문 상한 1024px).
- **데스크톱(768px 이상)**:
  - 왼쪽 고정 사이드바(240px, `--sidebar-bg`). 로고 "TravelPay"와 부제 "글로벌 여행 금융", 역할별 메뉴(메뉴마다 선 아이콘, 선택 메뉴는 배경과 아이콘 색으로 강조).
  - 사이드바 아래 계정 메뉴(경계선 아래): 내 정보(`/me`, 이름 표시) · 비밀번호 변경 · 로그아웃(hover 때 rose 톤). 모두 선 아이콘.
  - 본문 위 상단 바(바탕색 반투명 + 흐림, 테두리 없음, 위에 고정): 왼쪽 위치 표시("홈 / 지갑")와 환율 티커, 오른쪽 이름 첫 글자 아바타 + 이름.
- **모바일(768px 미만)**:
  - 상단 미니 헤더(52px): 로고, 아바타 + 이름(말줄임, "(관리자)" 숨김), "메뉴" 버튼. 메뉴 버튼은 사이드바를 서랍으로 엽니다(바깥 누름·Esc·화면 이동으로 닫힘).
  - 일반회원 하단 고정 탭바(56px): 홈 · 지갑·충전 · 송금(`/transfers/new`) · 환전 · 내역(`/payments`에서 시작, 거래내역 4화면에서 선택 표시). 아이콘 위·글자 아래, 선택 탭은 파랑. 본문 아래 72px 여백.
  - 환율 티커는 숨깁니다.
- **메뉴 분기**: 일반회원·관리자(`MASTER`)·비로그인 메뉴와 링크 텍스트·경로는 기존 그대로 둡니다(테스트·사용자 혼동 방지). 관리자에게는 하단 탭바와 환율 티커를 보이지 않습니다.
- **환율 티커(`RateTicker`)**: 서버가 지원하는 JPY·CNY만 고르고 매매기준율을 "100 JPY = 900.2 KRW"로 보여 줍니다. 환율은 레이아웃의 `RatesProvider`가 처음 1회와 5분마다만 조회하고 티커와 홈이 같은 응답을 씁니다. 통화를 바꿔도 다시 조회하지 않고, 실패하면 숨깁니다. 누르면 환율 화면으로 갑니다.

## 6. 화면별 규칙

### 홈 (`/`)

디자인 방향의 기준 화면입니다. 다른 화면도 이 구성(머리말 + 큰 제목, 강조 영역 하나, 흰 판넬 + 행)으로 맞춰 갑니다.

- 머리말 "안녕하세요, ○○님"(14px 회색) + 제목 "내 지갑"(24/28px).
- **잔액 영역**(블루 그라데이션 `#1d4ed8 → #1e3a8a`, 모서리 20px): 원화 잔액을 28/32px로 가장 크게. 통화를 합친 총액은 환산이 필요해 보여 주지 않습니다. 지갑이 없으면 "지갑 만들기", 조회 실패면 문구와 지갑 화면 링크.
- 잔액 영역 아래쪽에 자주 쓰는 기능 4개(충전·송금·결제·환전): 흰 사각 아이콘 + 이름.
- **보유 통화**: 판넬 안 행 목록. 통화 코드 원형 배지, 통화 이름·쓰임, 오른쪽 잔액(17px bold)과 "충전"/"원화로 환전" 링크.
- **오늘의 환율**: JPY·CNY 매매기준율과 전일 대비, "수수료 1%는 견적에서" 안내. 환율이 없으면 구역을 숨깁니다.
- **바로가기**: 거래내역·예약 환전·가맹점 관리(화살표 행).
- 데스크톱 1024px 이상은 2열(왼쪽 잔액·보유 통화, 오른쪽 환율·바로가기), 그 밖은 1열.
- 비로그인: 같은 블루 영역에 소개 문구와 로그인·회원가입, 아래 기능 소개 4개(아이콘), 환율 보기 링크. 잔액·환율을 부르지 않습니다.

### 지갑 (`/wallet`)

- 제목 줄(충전하기·송금하기) 아래 **보유 통화** 판넬(홈과 같은 통화 행: 원형 배지, 이름·쓰임, 잔액, "충전"/"원화로 환전")과 **최근 충전** 판넬(행 목록, "전체 보기").

### 충전 (`/wallet/charge`)

- 데스크톱 2열(1024px 이상): 왼쪽 폼 판넬(`.card`), 오른쪽 안내 박스. 좁으면 1열.
- 폼: 금액(+ 금액 칩), 은행 `select`(3자리 코드 문자열, 앞 0 유지), 계좌번호. 버튼 문구는 **충전하기**로 통일하고, 위에 "○○은행 계좌에서 ○○원을 출금해 충전합니다" 안내.
- 안내 박스: 처리 단계 정적 안내(접수 `REQUESTED` → 은행 출금 `BANK_PROCESSING` → 지갑 적립 `CREDIT_PROCESSING` → 완료 `COMPLETED`)와 환불·운영자 확인 설명, 상태 배지 범례. 지금 충전의 실제 상태가 아니므로 진행 표시를 하지 않습니다(실제 상태는 충전 상세).
- 테스트 계좌 버튼은 개발 환경에서만 보입니다(`VITE_LOCAL_TEST_ACCOUNT`). 실제 사용자 계좌로 대체하지 않습니다.
- 실제 정책상 필요한 한도·실명 일치 안내는 지우지 않습니다.

### 송금 (`/transfers/new`)

- 수취인 확인: 서버가 가린 이름(예: 박\*현)과 "송금 가능" 배지(`transferable`). 받을 수 없으면 오류 문구.
- 금액: 원화일 때만 금액 칩.
- 확인 화면: 받는 분·금액·**수수료 0원(보내는 금액만 빠집니다)**·메모. 송금 수수료는 백엔드에 없습니다.
- 완료하면 상세 화면으로 이동합니다(완료 모달 없음). 결과를 모르면(연결 실패·5xx) 실패로 단정하지 않고 같은 요청으로 다시 시도하거나 내역을 확인하게 합니다.

### 환전 (`/exchange`)

- 견적 전: 매매기준율과 수수료 1%를 참고값으로 표시(5초 갱신).
- 견적 확인: 적용 환율·수수료율(응답 `feeRate`), 남은 시간 배지("4:53 남음", 만료되면 "만료됨").

### 거래내역

- 충전·송금·환전·결제 내역 화면 위에 `HistoryTabs`를 둡니다. 각 탭은 자기 도메인의 사용자용 API만 부릅니다. 원장 감사용 API를 쓰지 않습니다.
- 네 도메인을 합쳐 주는 API가 없어 "전체" 탭은 두지 않습니다.

### 환율 (`/exchange-rates`)

- 목록 행 제목에 통화 원형 배지를 붙이고, 매매기준율과 전일 대비를 오른쪽에 둡니다.

### 목록·폼·상세 화면 공통

- 목록: 제목·탭은 바탕 위, 행 목록은 판넬. 빈 목록은 바탕 위 점선 상자.
- 폼: 제목·안내는 바탕 위, 입력은 판넬 안(입력·버튼 높이 44px).
- 상세: 송금·충전·결제·환전은 `.receipt`(작은 제목·큰 금액 가운데, 항목 판넬). 그 밖 상세는 정보 목록 판넬.
- 관리자 화면도 같은 공통 클래스를 따릅니다(필터 폼·목록·정보 목록이 판넬).

## 7. 넣지 않는 것

화면 예시나 와이어프레임에 있었지만 API·정책에 없어 넣지 않은 것입니다. 백엔드가 제공하면 다시 검토합니다.

| 항목 | 이유 |
|---|---|
| 실명인증 배지, "검증됨" | 수취인 조회 응답에 인증 필드가 없음(마스킹 이름·송금 가능 여부만) |
| "우대 100%", "면제 혜택" | 환전 수수료는 1%, 송금은 수수료 항목 자체가 없음 |
| 알림 벨·알림 팝오버·미확인 개수 | 알림 API 없음 |
| VIP 등급, "TLS 256-bit", 2FA 상태 | 데이터 없음 |
| 고객지원 화면(`/support`) | 화면·API 없음. 사이드바 보안 항목은 비밀번호 변경으로 대신함 |
| USD·EUR·VND 환율 | 서버 지원 통화는 JPY·CNY |
| 거래 후 잔액 | 송금·결제 응답에 없음 |
| 송금 완료 모달 | 완료 후 상세 화면 이동 유지(상세를 영수증 모양으로) |
| 거래내역 "전체" 탭 | 합쳐 주는 사용자용 API 없음 |
| 버튼·입력 컴포넌트 분리(`PrimaryButton`·`FormInput` 등) | 공통 클래스로 통일, 29개 화면 전면 수정 방지 |

## 8. 백엔드 연동 원칙

디자인보다 우선합니다. 자세한 규칙은 [공통 API 규칙](../guide/api-common.md)과 [개발 가이드](../guide/development.md)를 봅니다.

- 백엔드 API 명세를 바꾸지 않고, 실제 엔드포인트·요청·응답 DTO를 확인한 뒤 연동합니다.
- 인증·권한은 기존 구현(`RequireAuth`·`RequireRole`)을 따릅니다.
- 화면은 응답의 실제 상태값으로 그립니다. 응답이 없거나 불명확하면 성공을 만들지 않습니다.
- 금액은 최소 단위 정수(환전만 소수 문자열)로 다루고 소수 연산·문자열 이어 붙이기로 계산하지 않습니다.
- 금전 요청 중에는 버튼을 막고, API 오류·연결 실패·타임아웃을 구분해 안내합니다(5xx·타임아웃은 결과 모름).
- 테스트용 데이터(테스트 계좌 등)는 개발 환경에서만 보입니다.

## 9. 구현 수칙

- **구조 우선**: 폴더 구조·공통 레이아웃·API 클라이언트·라우팅을 먼저 확인하고 새 아키텍처를 들이지 않습니다.
- **의존성**: 디자인 때문에 라이브러리를 설치하지 않습니다.
- **변경 절차**: 화면 모양(색·간격·레이아웃)을 바꾸는 변경은 이 문서를 먼저 고치거나 합의를 받습니다. 정리(중복 제거·구조)만 하는 변경은 화면 차이가 없어야 합니다.
- **접근성**: 버튼·입력에 라벨을 둡니다. 아이콘만 있는 요소는 `aria-hidden`이나 접근 가능한 이름을 줍니다. 키보드로 쓸 수 있어야 하고, 서랍 메뉴는 Esc로 닫힙니다. 색만으로 상태를 구분하지 않습니다.
- **검증**: `npm test`·`npm run build`와 함께 375px·768px·1280px에서 레이아웃·카드·목록·폼·내비게이션을 브라우저로 확인합니다.
