# 화면

| `/transfers/new` | 송금하기: 수취인 확인(마스킹 이름 + "송금 가능" 배지) → 금액·통화·메모(원화면 금액 칩) → 확인(수수료 0원) → 송금. 완료하면 상세로 이동(모달 없음) | 필요 |
| `/transfers`, `/transfers/:transferId` | 송금 내역(전체·보낸·받은)·상세. `PROCESSING`이면 다시 조회, `REQUESTED`는 취소 가능. 받은 송금은 완료된 것만 `+`로 표시. 실패하면 `failureReason`별 안내(상세)와 짧은 사유(내역)를 보여 주되, 받은 송금에는 보낸 분의 잔액 부족을 알리지 않음 | 필요 |
| `/payments/new` | 결제하기: 가맹점 ID·통화·금액·결제 내용 → 확인 → 결제. `?merchantId=&currency=&amount=&paymentInfo=`로 미리 채움(가맹점 결제 링크) | 필요 |
| `/payments`, `/payments/:paymentId` | 결제 내역·상세. 상세에서 환불 신청(승인 후 3일 안)·신청 취소 | 필요 |
| `/merchant` | 가맹점 관리 입구: 가맹점 ID 입력(내 가맹점 목록 API가 없음), 최근 연 가맹점 | 필요 |
| `/merchant/:merchantId` | 가맹점 잔액, 정산 요약, 결제 링크 복사, 받은 결제(환불 신청 탭) | 필요 |
| `/merchant/:merchantId/payments/:paymentId` | 고객 환불 신청 처리: 환불 실행(부분·전액) 또는 거절 | 필요 |
| `/merchant/:merchantId/settlements` | 정산 미리보기·요청·내역. 정산 받을 지갑이 필요하다는 안내와 내 지갑 링크 | 필요 |
| `/merchant/:merchantId/settlements/:settlementId` | 정산 상세(포함된 결제) | 필요 |
| `/exchange` | 환전(원화→외화)·재환전(외화→원화): 금액 → 견적(5분) → 신청. 견적 전에는 매매기준율과 수수료 1%를 참고로 보여 주고 5초마다 갱신, 견적 뒤에는 견적 환율·수수료율(`feeRate`)만 표시 | 필요 |
| `/exchanges`, `/exchanges/:orderId` | 환전 내역(전체·환전·재환전)·상세(수수료율 포함). 예약으로 체결된 주문(응답 `reservationId`가 있음)은 내역에 "예약 체결" 배지, 상세에 예약 상세 링크 | 필요 |
| `/exchange-reservations/new` | 예약 환전: 목표 매매기준율·만료 기간(1·3·7·30일)을 걸면 조건에 닿을 때 서버가 환전. 지금 매매기준율은 5초마다 갱신 | 필요 |
| `/exchange-reservations`, `/exchange-reservations/:reservationId` | 예약 내역(대기·체결·취소·만료)·상세, 대기 예약 취소, 체결 주문으로 이동 | 필요 |
| 그 밖의 경로 | 404 안내 | 불필요 |

공통 레이아웃: 데스크톱(768px 이상)은 왼쪽 사이드바(아래쪽에 내 정보·비밀번호 변경·로그아웃)와 본문 위 상단 바(위치, 환율 티커 JPY·CNY 매매기준율 — 처음 1회와 5분마다 조회, 프로필), 모바일은 미니 헤더("메뉴" 버튼으로 사이드바 메뉴를 펼침)와 일반회원 하단 탭바(홈·지갑·충전·송금·환전·내역)입니다. 충전·송금·환전·결제 내역 화면 위에는 거래내역 탭이 있어 서로 오갑니다(합쳐 주는 API가 없어 "전체" 탭은 없음). 송금·충전·결제·환전 상세는 큰 금액을 가운데 두는 영수증 모양입니다. 사이드바·탭바 메뉴에는 선 아이콘이 붙고, 모든 화면은 제목·안내를 바탕 위에 두고 폼·목록·정보 목록만 흰 판넬로 띄웁니다. 화면 모양 규칙은 [스타일 가이드](../convention/style.md)를 봅니다.

관리자(`MASTER`)로 로그인하면 사이드바에 관리자 메뉴만 보이고, 위 표에서 로그인이 필요한 일반회원 화면(`/account/password` 제외)에 들어오면 관리자 첫 화면(`/admin`)으로 보냅니다. 반대로 일반회원이 `/admin/**`에 들어오면 `/`로 보냅니다.

| 경로 | 관리자 화면 |
|---|---|
| `/admin` | 처리 대기 건수(결제·환불·정산·환전·송금·충전), 지연 환불 신청 건수, 관리 기능 입구 |
| `/admin/reviews`, `/admin/reviews/:kind/:id` | 결제·환불·정산·환전 `MANUAL_REVIEW` 목록(사유 필터)·상세. 서버가 원장을 조회해 정한 결과로 처리하고, 처리 뒤 처리 기록으로 이동 |
| `/admin/merchants/new` | 가맹점 생성. 원장 계정을 못 만들면(202 `PENDING`) 원장 계정 재시도. 정산금이 주인 회원 지갑으로 들어가므로 주인이 지갑을 먼저 만들어야 한다는 안내를 입력·결과 화면에 표시 |
| `/admin/transfers`, `/admin/transfers/:transferId` | 전체 송금 목록(상태·회원·정렬)·상세(`reviewReason`·`failureReason`·`attemptCount`, 지갑 ID)·상태 변경 이력. `MANUAL_REVIEW`는 미리보기 → 확정 |
| `/admin/charges` | 전체 충전 목록(상태·회원). 관리자 단건 조회 API가 없어 항목을 목록에 모두 표시하고, `MANUAL_REVIEW`만 보정 화면으로 이동. 항목마다 회원 ID 복사 → 그 회원으로 필터. 주소의 `?userId=`가 UUID가 아니면 조회하지 않고 오류 표시 |
| `/admin/charges/:chargeId/review` | 충전 보정: 지금 은행 출금·환불·원장 사실, 가능한 조치와 불가 이유 → 조치·사유(·대사 결과 ID)로 보정. 재개(원장 적립·은행 환불 단계)는 완료가 아니라 "처리 중, 완료 시점 미정"으로 안내하고 그 상태로 거른 충전 목록 링크를 줌(다시 조회하지 않음) |
| `/admin/charges/reconciliations`, `/admin/charges/reconciliations/:runId` | 충전 대사 수동 실행(기간 생략 또는 지정)·실행 기록·어긋남 결과(종류 필터). 확인 중 충전의 결과에서 보정 화면으로 이동. 요약 아래에 어긋남 합계 안내 |
| `/admin/resolutions`, `/admin/resolutions/:domain/:targetId` | 처리 기록(결제·환불, 정산, 환전 탭, 종류·처리 담당자·대상 ID 필터)·대상별 처리 기록 상세 |
| `/admin/refund-requests/overdue` | 신청 후 3일 넘게 처리되지 않은 환불 신청(오래된 순, 경과 시간). 항목에서 관리자 결제 상세로 이동 |
| `/admin/payments` | 가맹점 결제 조회: 가맹점 ID로 결제 목록(상태 탭), 결제 ID까지 넣으면 상세로 바로 이동. 관리자 결제 검색·가맹점 목록 API가 없어 가맹점 ID가 필요 |
| `/admin/merchants/:merchantId/payments/:paymentId` | 관리자 결제 상세: 고객 환불 신청을 가맹점 대신 실행(부분·전액)하거나 거절. 신청 없는 결제 완료 결제는 직접 환불(기간 제한 없음). 정산에 들어간 결제는 관리자도 환불 불가 |
| `/admin/users` | 회원 검색(회원 ID·이메일·휴대폰 번호·상태, 정확히 일치, 개인정보는 서버가 가림)·정지/해제·기존 세션 종료. 단건 조회 API가 없어 검색 결과 줄에서 처리하고, 본인 계정은 정지 버튼을 숨김. 검색 조건은 개인정보라 화면 주소에 남기지 않음 |

처리 중인 송금·결제·환불·정산·환전 상세는 3초마다 최대 2분 다시 조회합니다. 환율(환율·예약 신청·견적 전 환전 입력)은 5초마다 다시 조회하되, 탭이 보이지 않으면 멈추고 앞 조회가 끝나기 전에는 새로 보내지 않으며, 실패하면 마지막으로 받은 값을 유지합니다. 예약 상세는 대기가 며칠씩 이어질 수 있어 자동으로 다시 조회하지 않고 새로고침 버튼을 둡니다.

## 미구현·제약

- 회원 정지·해제와 세션 종료는 결과를 모를 때 다시 보내도 같은 결과입니다(같은 상태면 그대로, 세션 종료는 기존 세션만 끝냄). 약관 등록은 멱등성 키가 없지만 같은 코드·버전을 다시 보내면 409라 두 번 생기지 않습니다.
- 약관 목록의 "시행 중"은 공개 약관 조회(`GET /api/v1/terms`)와 맞춰 표시합니다. 그 조회가 실패하면 시행 예정만 구분합니다.
- 송금 확정과 충전 보정은 서버가 실행 순간 원장(충전은 은행·원장)을 다시 조회해 판단합니다. 화면의 미리보기·확인 결과는 실행 허가가 아니라서, 그 사이 상태가 바뀌면 거절됩니다(송금 409 `TRANSFER_RESOLUTION_MISMATCH` → 다시 미리보기, 충전 409 `CHARGE_RESOLUTION_REJECTED` → 다시 확인).
- 송금 확정에서 502·503·504는 서버가 원장 조회 실패로 반영하지 않은 경우와 Gateway 문제를 구분할 수 없어 결과 모름으로 다룹니다. 확정 본문을 잠그고 같은 내용으로만 다시 보냅니다(같은 운영자·같은 본문이면 서버가 현재 상태를 돌려줌).
- 처리 기록 API에 단건 조회가 없어, 처리 기록 상세는 대상 ID로 거른 기록(최대 100건)을 모두 보여 줍니다. 송금 확정 이력은 송금 상세, 충전 보정 결과는 보정 화면에서만 봅니다.
- 충전 대사 기간은 서버 기본 설정상 1일 이하, 끝은 지금보다 5분 이전이어야 합니다(어기면 400). 수동 실행은 끝까지 대사한 뒤 응답합니다.
- 송금 목록의 기간·통화 필터, 환전 처리 기록의 기간 필터는 서버가 지원하지만 화면에는 없습니다.
- 예약 환전은 예약할 때 잔액을 묶지 않습니다. 체결 때 잔액이 부족하면 예약은 `EXECUTED`, 만들어진 주문은 `FAILED`입니다.
- 예약 만료 30일은 서버 시각 기준 상한이라, 기기 시계 차이로 거절되지 않게 1시간 일찍 만료합니다(화면에 실제 만료 시각 표시).
- 결제자가 가맹점을 검색·확인하는 API가 없어, 가맹점 이름과 받는 통화는 결제를 시도해야 알 수 있습니다(통화가 다르면 `PAYMENT_CURRENCY_MISMATCH`).
- 내 가맹점 목록 API가 없어 가맹점 주인은 가맹점 ID로 들어갑니다. 최근 연 ID는 이 브라우저의 localStorage에만 남습니다.
- 견적 전 수수료율 API가 없어 견적 전 화면의 수수료 1%는 서버 설정과 같은 고정값(`features/exchange/rateDisplay.tsx`의 `PRE_QUOTE_FEE_RATE`)입니다. 서버 설정이 바뀌면 같이 바꿉니다. 환전 내역 목록 응답에는 `feeRate`가 없어 수수료율은 견적 확인·환전 상세에만 보입니다.
- 매매기준율 강조(시각 변경)는 시안 확인 뒤 반영할 예정이라 아직 적용하지 않았습니다.
- 결제 응답에 정산 여부가 없어, 관리자 화면은 정산 제한을 늘 안내하고 실제로는 환불 실행이 409 `PAYMENT_ALREADY_SETTLED`로 거절될 때 환불 버튼을 숨깁니다.
- 충전 보정 재개 뒤의 결과는 관리자 충전 목록에서 확인합니다. 확인 API는 `MANUAL_REVIEW` 전용이고 관리자 충전 단건 조회 API와 완료 시점 보장이 없어, 화면이 다시 조회하지 않습니다. 보정 결과에 회원 ID가 없어 목록 링크에는 상태 필터만 겁니다.
- 관리자 충전 목록을 회원으로 걸렀을 때 빈 목록이면, 그 회원의 충전이 없는 것인지 없는 회원인지 구분하지 않습니다(서버가 둘 다 빈 목록으로 응답).
- 충전 대사의 어긋남에는 충전이 없는 은행·원장 거래도 들어가 대상·일치·어긋남·보류 건수의 합이 맞지 않을 수 있습니다.
- 정산 대상은 결제 승인 후 환불 기간 3일 + 여유 1시간이 지난 결제라, 로컬에서 바로 확인하면 `PAYMENT_NO_SETTLEMENT_TARGET`이 나옵니다.
